# ARCHITECTURE.md — как устроен проект

Документ описывает три вещи: как лежат файлы, как устроена игра (вертикальный срез) и как устроена среда для агентов (Harness). Сюжет и механики описаны в `docs/GDD.md`, порядок работ — в `PLAN.md`.

## 1. Репозиторий

Проект Unreal лежит **в корне репозитория**. Причина: редактор создаёт `.mcp.json` рядом с `.uproject`, а Claude Code ищет его в папке, где запущен. Один корень — никакой путаницы.

```
altyn-adam/
├── AGENTS.md              правила для агентов
├── CLAUDE.md              вход для Claude Code (подключает AGENTS.md)
├── ARCHITECTURE.md        этот файл
├── PLAN.md                этапы и задачи
├── README.md
│
├── .claude/               Harness: среда для агентов
│   ├── settings.json      плагин Epic, хуки, запреты
│   ├── agents/            роли (planner, gameplay-engineer, ...)
│   ├── skills/            команды (/next-task, /ue-checkpoint, /done, /gdd-check)
│   └── hooks/             защитные скрипты
├── .github/               CI и шаблон pull request
├── scripts/check-repo.sh  проверка репозитория (локально и в CI)
│
├── docs/
│   ├── GDD.md             дизайн-документ v1.1 (источник истины)
│   ├── DEVLOG.md          журнал сделанного
│   ├── decisions/         записи решений (ADR)
│   ├── setup/SETUP.md     установка с нуля
│   ├── tasks/             планы задач
│   └── third-party-assets.md
│
├── AltynAdam.uproject     ┐
├── Config/                │ проект Unreal Engine 5.8
├── Content/               │ (появится на этапе M0)
├── Source/                ┘
└── .mcp.json              создаётся редактором, хранится в git
```

### Что хранится в git и как

| Что | Где | Как хранится |
|---|---|---|
| Документы, код, конфиги | весь репозиторий | обычный git |
| Свои ассеты (`.uasset`, `.umap`, звук, исходники арта) | `Content/AltynAdam/`, `SourceArt/` | Git LFS (`.gitattributes`) |
| Купленные и скачанные наборы | `Content/ThirdParty/` | **не в git**, список в `docs/third-party-assets.md` |
| Кэш и сборки (`Binaries`, `Intermediate`, `Saved`, `DerivedDataCache`) | — | не в git (`.gitignore`) |

Сторонние наборы не хранятся в git по двум причинам: они большие (квота Git LFS на GitHub ограничена) и их лицензии обычно запрещают распространение. Цена решения: после свежего клонирования наборы нужно скачать заново по списку.

## 2. Игра: вертикальный срез

### 2.1 Что должно работать

Акт 1.1 (день): герой просыпается, говорит с людьми, едет верхом к реке, пригоняет табун, вечером слушает историю матери.
Акт 1.2 (ночь): нападение, стелс без боя, сцена с матерью, бегство верхом под стрелами.

### 2.2 Код и Blueprint

Гибридная схема, стандартная для Unreal: **логика систем — в C++, настройка и содержимое — в Blueprint и Data Asset**.

Почему так, хотя в GDD изначально стояло «сначала Blueprints»: с агентами расчёт меняется. C++ — это текст, агент пишет его напрямую, а вы видите каждое изменение в git построчно. Blueprint — бинарный файл: агент может править его через редактор, но изменения в git не читаются и не проверяются ревью. Решение принято владельцем: `docs/decisions/0004-cpp-blueprint-split.md`.

```
Source/AltynAdam/
├── Core/          GameMode, GameInstance, настройки, логирование
├── Character/     AAltynCharacter (герой), компоненты взаимодействия
├── Mount/         слой-обёртка над системой верховой езды
├── Stealth/       заметность героя, шум, укрытия
├── AI/            персидский воин: восприятие, состояния
├── Objectives/    цели и ход дня
├── Dialogue/      реплики и субтитры
└── UI/            базовые классы виджетов

Content/AltynAdam/
├── Characters/    Hero, Mother, Father, Elder, Persians
├── Horse/
├── AI/
├── Levels/        L_GoldenCamp (+ L_Sandbox на этапе обучения)
├── Cinematics/    LS_ (Sequencer)
├── Data/          DA_, DT_ (реплики, цели, параметры)
├── UI/
├── Audio/
└── _Sandbox/      учебные прототипы этапа M1, в срез не входят
```

### 2.3 Системы

| Система | Задача в срезе | На чём строится |
|---|---|---|
| Персонаж | Ходьба, бег, присед, взаимодействие | `ACharacter`, Enhanced Input, Animation Blueprint |
| Конь | Сесть и слезть, галоп, прыжок, свой конь героя | Готовая система с Fab за слоем `Mount/` |
| Стелс | Заметность, шум, укрытия, отвлечение | Компонент заметности + AI Perception |
| ИИ воина | Патруль → подозрение → поиск → поимка | AI Perception + Behavior Tree или State Tree (выбор на M1) |
| Цели и ход дня | Последовательность заданий Акта 1.1, переход день → ночь | Подсистема целей, данные в Data Asset |
| Диалоги | Короткие реплики, субтитры | Data Table + виджет |
| Катсцены | Старец, история у огня, гибель матери | Sequencer |
| Чекпойнты | Перезапуск при поимке | Простое сохранение точки |
| Интерфейс | Подсказки управления, текущая цель | UMG |

**Конь — ядро игры, но не самописный.** Анимация всадника и лошади — самая дорогая часть проекта. Берётся готовая система, а весь остальной код обращается к ней только через слой `Mount/` (интерфейс «сесть», «слезть», «скорость», «прыжок»). Если система не подойдёт, меняется один слой, а не вся игра.

**Стелс без боя.** Герой — ребёнок. Поимка означает перезапуск с чекпойнта. Боевой системы в срезе нет вообще.

**День и ночь — один уровень.** `L_GoldenCamp` имеет два состояния (день и нападение), которые переключаются через слои данных или подуровни. World Partition и открытый мир для среза не нужны.

### 2.4 Данные вместо кода

Реплики, список целей дня, параметры зрения и слуха воинов, скорости коня — в Data Asset и Data Table. Так владелец может менять баланс и тексты в редакторе без программирования, а агент не трогает код ради числа.

### 2.5 Тесты

- Автотесты Unreal (Automation) для логики, которую можно проверить без игрока: цели, заметность, переходы состояний ИИ.
- Запуск через `unreal-mcp` (набор инструментов тестирования) в конце каждой задачи с кодом.
- Игровые ощущения проверяются только руками: раздел «Как проверить руками» в каждой записи DEVLOG.

## 3. Harness: среда для агентов

Harness — это всё, что окружает модель и делает её работу предсказуемой: инструкции, роли, команды, защитные хуки и проверки.

### 3.1 Слои

```
Владелец
   │  задаёт цель, утверждает план, сливает pull request
   ▼
Основная сессия Claude Code  ── читает CLAUDE.md → AGENTS.md
   │
   ├── роли (.claude/agents)      planner · gameplay-engineer · world-builder
   │                              narrative-keeper · qa-reviewer
   ├── команды (.claude/skills)   /next-task · /ue-checkpoint · /done · /gdd-check
   ├── хуки (.claude/hooks)       проверяют действия до их выполнения
   │
   ├── файлы и git                код, документы
   └── unreal-mcp (плагин Epic)   живой Unreal Editor на localhost:8000
                                        │
CI на GitHub ── scripts/check-repo.sh ──┘ проверяет каждый push и pull request
```

### 3.2 Плагин Epic

`unreal-engine-skills-for-claude-code` включён в `.claude/settings.json`. Он даёт навык `unreal-mcp` и доступ к инструментам редактора: акторы, Blueprint, материалы, Sequencer, State Tree, виджеты, автотесты. Требования: Unreal Engine 5.8, включённые плагины Unreal MCP и All Toolsets, запущенный редактор с сервером MCP.

Плагин экспериментальный, а доступ, который он даёт, равен запуску произвольного кода в редакторе. Поэтому действуют правила из раздела 5 `AGENTS.md` и хуки ниже.

### 3.3 Хуки

| Хук | Когда срабатывает | Что делает |
|---|---|---|
| `session-context.sh` | начало сессии | сообщает агенту текущий этап, ближайшие задачи и состояние git |
| `guard-bash.sh` | перед командой в терминале | блокирует `push --force`, `reset --hard`, рекурсивное удаление папок проекта и подобное |
| `protect-files.sh` | перед записью файла | блокирует запись бинарных ассетов как текста; для GDD и файлов Harness просит подтверждение владельца |
| `ue-checkpoint-guard.sh` | перед первым вызовом `unreal-mcp` за сессию | требует чистого рабочего дерева, то есть чекпойнта |

Хуки написаны на bash без зависимостей. На Windows нужен Git for Windows (он же нужен плагину Epic).

### 3.4 Проверки

`scripts/check-repo.sh` проверяет то, что можно проверить без движка: обязательные файлы на месте, `settings.json` корректен, у ролей и команд есть описания, бинарные ассеты идут через LFS, в git нет кэша и секретов, в `PLAN.md` указан текущий этап. Тот же скрипт запускает GitHub Actions.

Сборка Unreal в облачном CI не делается: движок слишком велик для бесплатных серверов GitHub. Сборка и автотесты выполняются локально через редактор.

### 3.5 Поток одной задачи

```
/next-task → planner (Plan Mode) → план в docs/tasks/ → владелец утверждает
          → /ue-checkpoint → исполнитель работает → проверки
          → /done → qa-reviewer → PLAN.md + DEVLOG.md → pull request → владелец сливает
```
