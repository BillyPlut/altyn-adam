# AGENTS.md — правила для агентов проекта Altyn Adam

Этот файл читает каждый агент в начале работы. Он короткий намеренно: всё, что здесь написано, обязательно.

## 1. Проект в трёх строках

Altyn Adam — линейная action-adventure игра в духе Assassin's Creed II про эпоху саков (VI в. до н.э.).
Сейчас делается только **вертикальный срез: Акты 1.1–1.2** (обычный день в стане и ночное нападение, 20–30 минут игры).
Движок — Unreal Engine 5.8. Разработчик один, агенты работают через Claude Code и официальный MCP-плагин Epic.

## 2. Где лежит истина

| Вопрос | Файл | Кто меняет |
|---|---|---|
| Что мы делаем (сюжет, тон, механики) | `docs/GDD.md` | только владелец |
| Как это устроено (код, папки, системы, роли агентов) | `ARCHITECTURE.md` | агент, после согласования |
| Что делать сейчас и что дальше | `PLAN.md` | агент отмечает задачи, этапы меняет владелец |
| Почему так решили | `docs/decisions/` | агент добавляет, не переписывает |
| Что было сделано | `docs/DEVLOG.md` | агент дописывает в конец |
| Чужие ассеты и лицензии | `docs/third-party-assets.md` | агент дописывает |

Если два файла противоречат друг другу, прав тот, что выше в таблице. О противоречии сообщи владельцу. Исключение: принятое владельцем решение из `docs/decisions/`, которое прямо уточняет GDD (сейчас это 0004).

## 3. Владелец проекта

Владелец — соло-разработчик и **новичок в Unreal Engine**. Он пишет по-русски. Из этого следует:

- Отвечай по-русски, простыми словами. Термин движка при первом упоминании объясняй одной фразой.
- После каждой задачи пиши раздел «Как проверить руками»: что открыть в редакторе, что нажать, что должно произойти.
- Не делай за владельца то, чему он учится на этапе M1: показывай, объясняй, оставляй небольшой кусок ему.
- Одно решение за раз. Если есть развилка, предложи 2–3 варианта и отметь свой совет.

## 4. Рабочий цикл

1. `/next-task` — взять следующую задачу из `PLAN.md`. Планировщик (`planner`) готовит план в режиме Plan Mode, ничего не меняя.
2. Владелец утверждает план. Без утверждения к работе не приступать.
3. `/ue-checkpoint` — коммит-чекпойнт перед любыми изменениями в редакторе.
4. Работа: код, редактор через `unreal-mcp`, документы.
5. Проверка: `bash scripts/check-repo.sh`, сборка и тесты, если затронут код.
6. `/done` — ревью (`qa-reviewer`), отметка в `PLAN.md`, запись в `docs/DEVLOG.md`, коммит, pull request.

## 5. Жёсткие правила

**Объём работ**
- Делается только текущий этап из `PLAN.md`. Бой, выживание, система Памяти, открытый мир и Акты 1.3+ не строятся, пока срез не готов.
- Одна задача — одна ветка `task/<ID>-<кратко>` — один pull request. Одновременно открыта только одна ветка: бинарные ассеты Unreal не сливаются.

**GDD и культура**
- `docs/GDD.md` не редактируется без прямого указания владельца.
- Любой текст, имя, костюм, предмет или обряд, который попадает в игру, сверяется с GDD (`/gdd-check`).
- Исторические факты не выдумываются. Если это допущение, так и пиши: «допущение». Если не уверен, пиши «нужно проверить по источникам».
- Assassin's Creed — источник вдохновения по структуре. Имена, персонажи, символика, интерфейс и ассеты Ubisoft и любых других игр не используются.

**Редактор и ассеты**
- Файлы `.uasset` и `.umap` бинарные. Их нельзя создавать или править как текст. Только через редактор (`unreal-mcp`).
- Перед первой правкой в редакторе за сессию рабочее дерево должно быть чистым (это проверяет хук).
- `execute_tool_script` выполняет произвольный Python внутри редактора. Используй его, только когда узких инструментов не хватает, и перед вызовом напиши владельцу, что именно сделает скрипт.
- Claude Code не запускается с `--dangerously-skip-permissions`.
- Купленные и скачанные наборы ассетов кладутся в `Content/ThirdParty/` (не хранится в git) и записываются в `docs/third-party-assets.md` с источником и лицензией.

**Git**
- Маленькие коммиты с префиксом: `feat:`, `fix:`, `docs:`, `chore:`, `checkpoint:`.
- Запрещены `git push --force`, `git reset --hard`, переписывание истории, удаление веток без просьбы владельца.
- Секреты, ключи и `.env` в репозиторий не попадают.
- В `main` напрямую не пушить. Слияние делает владелец через pull request.

**Harness**
- Файлы `.claude/settings.json`, `.claude/hooks/*`, `.github/workflows/*` меняются только с подтверждения владельца (хук спросит).
- Если хук заблокировал действие, не ищи обход. Сделай то, что он просит, или спроси владельца.

## 6. Правила кода

- Идентификаторы и комментарии в коде — на английском. Тексты игры и документы — на русском (язык локализации см. открытые вопросы в `PLAN.md`).
- C++: префиксы Unreal (`A` актор, `U` объект/компонент, `F` структура, `E` enum, `I` интерфейс), класс проекта начинается с `Altyn` (`AAltynCharacter`). Один класс — одна пара файлов.
- Логика систем живёт в C++ или в базовых Blueprint-классах, настройка значений — в Data Asset и Blueprint-наследниках. Подробности в `ARCHITECTURE.md`.
- Ассеты: `BP_`, `WBP_`, `BT_`, `BB_`, `ST_`, `DA_`, `DT_`, `L_`, `SK_`, `SM_`, `M_`, `MI_`, `T_`, `A_`, `ABP_`, `LS_`, `IA_`, `IMC_`. Всё своё — в `Content/AltynAdam/`.
- Магических чисел нет: скорость, радиус слуха, угол зрения выносятся в настраиваемые свойства с понятным именем.
- Сторонняя система (например, верховая езда) подключается через свой слой-обёртку, чтобы её можно было заменить.

## 7. Роли агентов

| Агент | Что делает | Что не делает |
|---|---|---|
| `planner` | Изучает задачу и готовит план в Plan Mode | Ничего не меняет |
| `gameplay-engineer` | Системы игры: персонаж, конь, стелс, цели, диалоги | Не строит уровни и арт |
| `world-builder` | Уровни, «серая коробка», свет, PCG, Sequencer | Не пишет игровую логику |
| `narrative-keeper` | Сверка с GDD, сценарии сцен, тексты, историческая аккуратность | Не трогает код и ассеты |
| `qa-reviewer` | Ревью изменений, проверки, чек-лист «готово» | Не исправляет сам, только сообщает |

Определения лежат в `.claude/agents/`.

## 8. Определение «готово»

Задача готова, когда выполнено всё:

- [ ] Критерии приёмки из плана задачи выполнены и проверены в редакторе (Play In Editor).
- [ ] `bash scripts/check-repo.sh` проходит.
- [ ] Если менялся код: проект собирается, автотесты проходят.
- [ ] `/gdd-check` пройден, если затронуты тексты, персонажи или культура.
- [ ] `qa-reviewer` не нашёл блокирующих замечаний.
- [ ] В `PLAN.md` стоит отметка, в `docs/DEVLOG.md` есть запись с разделом «Как проверить руками».
- [ ] Новое решение записано в `docs/decisions/`, если оно было принято.

## 9. Когда остановиться и спросить

- Задача требует выйти за текущий этап или противоречит GDD.
- Нужно купить, скачать или подключить что-то стороннее.
- Действие нельзя отменить (удаление ассетов, массовое переименование, миграция).
- Редактор или MCP-сервер ведут себя неожиданно: плагин экспериментальный, не продолжай вслепую.
- Ты не уверен, что понял задачу. Один уточняющий вопрос дешевле часа переделок.
