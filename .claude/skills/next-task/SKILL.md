# Следующая задача

Цель: выбрать задачу, получить план от `planner` и дождаться решения владельца. На этом шаге в проекте ничего не меняется.

1. Прочитай `PLAN.md`. Найди строку «Текущий этап».
2. Выбери задачу:
   - если передан аргумент (`$ARGUMENTS`), возьми задачу с этим ID;
   - иначе возьми первую невыполненную (`- [ ]`) задачу текущего этапа.
3. Проверь:
   - задача относится к текущему этапу. Если нет — сообщи владельцу и остановись;
   - задача помечена 👤. Тогда не делай её сам: объясни владельцу по шагам, что нужно сделать (для этапа M0 — по `docs/setup/SETUP.md`), и спроси, когда будет готово;
   - нет другой открытой ветки `task/...` с незавершённой работой (`git branch --list 'task/*'`). Если есть — сначала закончить её.
4. Передай задачу агенту `planner`. Он вернёт план по шаблону `docs/tasks/_TEMPLATE.md`.
5. Покажи план владельцу целиком и спроси: утвердить, изменить или отложить.
6. Только после слов владельца «утверждаю» (или равнозначных):
   - создай ветку `task/<ID>-<кратко-латиницей>`;
   - сохрани план в `docs/tasks/<ID>-<кратко>.md` со статусом «утверждён»;
   - сделай коммит `docs: plan <ID>`;
   - если задача затронет редактор, напомни про `/ue-checkpoint`.

Не начинай исполнение в этом же шаге. Исполнение — отдельное сообщение владельца.
