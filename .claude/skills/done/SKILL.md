# Завершение задачи

Цель: задача либо честно закрыта по определению «готово» из `AGENTS.md`, либо возвращена на доработку с понятным списком.

1. Найди план задачи в `docs/tasks/` по имени текущей ветки.
2. Пройди критерии приёмки из плана. По каждому напиши, как он проверен. Непроверенный критерий — это не «готово».
3. Запусти `bash scripts/check-repo.sh`. Ошибки исправь.
4. Если менялся код: сборка и автотесты через `unreal-mcp`. Если редактор закрыт — попроси владельца открыть его; не пропускай этот шаг молча.
5. Если затронуты тексты, персонажи, предметы или обряды — выполни `/gdd-check`.
6. Передай изменения агенту `qa-reviewer`.
   - Есть «Блокирует» — исправь через исполнителя и повтори ревью.
   - Нет — дальше.
7. Обнови документы:
   - `PLAN.md`: отметь задачу `[x]`. Этапы и ворота не трогай;
   - `docs/DEVLOG.md`: новая запись в конец по формату из файла, обязательно с разделом «Как проверить руками»;
   - статус в плане задачи — «готово»;
   - `docs/decisions/` и `docs/third-party-assets.md` — если было решение или новый сторонний ассет.
8. Коммит и публикация ветки:
   ```
   git add -A
   git commit -m "<feat|fix|docs|chore>: <ID> <что сделано>"
   git push -u origin <текущая ветка>
   ```
9. Открой pull request в `main` (через `gh pr create`, если установлен GitHub CLI, иначе дай владельцу ссылку). В описании: что сделано, как проверить руками, что ревьюер не смог проверить.
10. Скажи владельцу, что нужно посмотреть в редакторе перед слиянием. Сливает pull request владелец.

Если закрыта последняя задача этапа, не переходи к следующему этапу сам: перечисли условия «ворот» из `PLAN.md` и спроси владельца, выполнены ли они.
